### M0-c 認証と権限

**着手前レビューで権限マトリクスを一次情報から入手できた。**
出典: https://support-ja.backlog.com/hc/ja/articles/360035643434
`docs/00-spec-verified.md` 7.1 に全表を写した。実装に効いた発見:

1. **課題の削除は管理者とプロジェクト管理者だけ。** 制限なしの一般ユーザーでもできない
2. **「課題の登録のみ」は追加できるが編集できない。** 自分が作った課題も編集できない
3. **「課題の閲覧のみ」はコメントも付けられない**
4. **種別・カテゴリー・バージョンは「制限なし」の一般ユーザーでも編集できる。**
   プロジェクト管理者専用ではない
5. **共有ファイルは閲覧すら制限ユーザーに許されない。** 課題・Wikiと扱いが違う
6. 「追加権限」(契約管理者/プロジェクト管理者/メンバー招待/チーム管理者)という
   軸が設計書v2から抜けていた

`can()` は3軸のまま実装し、権限マトリクスを表のままテストデータに起こした。
131件のテストが通る。表が更新されたら配列を直すだけで漏れが落ちる。

### 詰まったこと

**Auth.js のリダイレクト先が http://0.0.0.0:3000 になり到達不能だった。**
Next を `-H 0.0.0.0` で起動しているため、Auth.js v5 が内部で作るURLが
バインドアドレスから組み立てられる。`AUTH_TRUST_HOST=true` も
`X-Forwarded-Host` の明示も効かなかった。

入口が LAN・Tailscale・職場VM と複数あり、設定でホスト名を固定したくないため、
Caddy の `header_down Location "^https?://0\.0\.0\.0:3000" ""` で
オリジンを剥がして相対パスにした。3経路すべてで正しく戻ることを確認済み。

**コンテナが root で動いており生成物が root 所有になっていた。**
マイグレーションやPrismaクライアントをホストから触れず、gitにも追加できない。
`user: "1000:1000"` で動かすよう変更した。

**pnpm 9 が依存のビルドスクリプトを既定で止める。**
`pnpm install` のたびにPrismaクライアントが消えるため、
`pnpm.onlyBuiltDependencies` と `postinstall: prisma generate` を追加した。
