### M0-c 認証と権限

**着手前レビューで権限マトリクスを一次情報から入手できた。**
出典: https://support-ja.backlog.com/hc/ja/articles/360035643434
`docs/00-spec-verified.md` 7.1 に全表を写した。実装に効いた発見:

1. **課題の削除は管理者とプロジェクト管理者だけ。** 制限なしの一般ユーザーでもできない
2. **「課題の登録のみ」は追加できるが編集できない。** 自分が作った課題も編集できない
3. **「課題の閲覧のみ」はコメントも付けられない**
4. **種別・カテゴリー・バージョンは「制限なし」の一般ユーザーでも編集できる。**
   プロジェクト管理者専用ではない
5. **共有ファイルは閲覧すら制限ユーザーに許されない。** 課題・Wikiと扱いが違う
6. 「追加権限」(契約管理者/プロジェクト管理者/メンバー招待/チーム管理者)という
   軸が設計書v2から抜けていた

`can()` は3軸のまま実装し、権限マトリクスを表のままテストデータに起こした。
131件のテストが通る。表が更新されたら配列を直すだけで漏れが落ちる。

### 詰まったこと

**Auth.js のリダイレクト先が http://0.0.0.0:3000 になり到達不能だった。**
Next を `-H 0.0.0.0` で起動しているため、Auth.js v5 が内部で作るURLが
バインドアドレスから組み立てられる。`AUTH_TRUST_HOST=true` も
`X-Forwarded-Host` の明示も効かなかった。

入口が LAN・Tailscale・職場VM と複数あり、設定でホスト名を固定したくないため、
Caddy の `header_down Location "^https?://0\.0\.0\.0:3000" ""` で
オリジンを剥がして相対パスにした。3経路すべてで正しく戻ることを確認済み。

**コンテナが root で動いており生成物が root 所有になっていた。**
マイグレーションやPrismaクライアントをホストから触れず、gitにも追加できない。
`user: "1000:1000"` で動かすよう変更した。

**pnpm 9 が依存のビルドスクリプトを既定で止める。**
`pnpm install` のたびにPrismaクライアントが消えるため、
`pnpm.onlyBuiltDependencies` と `postinstall: prisma generate` を追加した。

### できるようになったこと

- **Gitea をウィザードなしで構成**: 設定は compose の `GITEA__*` に集約し、
  `INSTALL_LOCK=true` で起動時にDBマイグレーションまで自動。
  残りは `scripts/gitea-setup.sh`（管理者ユーザーとアクセストークン）
- **ユーザーと organization の同期**: プロジェクト=organization、
  参加ユーザー=Gitea ユーザー。`git.access` を持つ人だけを入れる
- **リポジトリ作成**: 画面から作ると organization・メンバー・webhook まで用意
- **push → 課題コメント**: コミットメッセージの課題キーから自動登録。
  リポジトリ単位のON/OFFで止められる
- **PR連携**: ブランチ名の課題キーから関連課題を自動で付ける。
  一覧・詳細・関連課題の付け替え
- **リポジトリ閲覧**: ファイルツリー・中身（行番号付き）・コミット一覧・差分
- **API v2**: `git/repositories` と `pullRequests`（件数・単体・絞り込み）
- **Gitea の個人設定**: 自分のパスワードを決められる（`/settings/git`）

### 受け入れ条件

| 条件 | 結果 |
|---|---|
| コミットして push すると該当課題にコメントが自動で付く | 達成。「AA-1 と AA-2 をまとめて直した」で2課題に登録 |
| 課題からコミット、コミットから課題の双方向に辿れる | 達成。課題ページにGitの節、コミット詳細に関連課題 |

### 詰まったこと

**Gitea の予約名に当たった。** `admin` はユーザー名として使えない
（422 `name is reserved`）。アプリの管理者がちょうどこれ。
`users.gitea_login` と `projects.gitea_org` を足し、衝突時は `-kadai` を
付けた名前を振って記録するようにした（`admin` → `admin-kadai`、
キー `API` → `API-kadai`）。

**メールの重複も拒まれる。** しかも付け替えた古いアドレスは非プライマリの
まま残り、予約を続ける。`/users/search` はメールを返さないことがあるため、
確認は `/admin/emails` で行う。

**Gitea は登録済み webhook の秘密を返さない。** 既存 hook をそのまま使う
実装だと、`GITEA_WEBHOOK_SECRET` を変えたときに配信が静かに全部401になる。
毎回 PATCH で入れ直すようにした。

**Caddy の設定を一度壊した。** Gitea 本体はルート配下で配信し、
`ROOT_URL` の `/git/` は生成するリンクにだけ使う。404 の原因は
インストール未完了だったのに、プレフィックスの付け外しを疑って変更した。

**ルートファイルから補助関数をエクスポートすると本番ビルドが落ちる。**
Next.js はルートのエクスポートをハンドラだけに限っている。
